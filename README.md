# Lube Control

Сайт для контроля остатков масла на стеллажах, которые стоят на СТО.
Продавец на точке отмечает продажу в один тап, владелец сети в реальном времени
видит остатки по всем стеллажам и знает, куда и что везти.

Работает без сервера и сборки: два файла в корне репозитория и GitHub Pages.

---

## Что внутри

| Файл | Зачем |
|---|---|
| `index.html` | Весь сайт: стили, скрипты, все экраны. Больше ничего не нужно |
| `config.js` | Настройки: пороги, бонус, цвета, надписи, категории, аккаунты, ключи базы |
| `schema.sql` | Схема базы для Supabase. Нужна, только если хотите общую базу на все устройства |
| `.nojekyll` | Служебный пустой файл, чтобы GitHub Pages отдавал сайт как есть |

---

## Запуск за 5 минут

1. Создайте новый репозиторий на GitHub (публичный).
2. Загрузите в **корень** репозитория `index.html`, `config.js` и `.nojekyll`.
3. Settings → Pages → Source: **Deploy from a branch** → ветка `main`, папка `/ (root)` → Save.
4. Через минуту сайт открыт по адресу `https://<ваш-логин>.github.io/<репозиторий>/`.
5. Входите: `admin` / `Oil-Admin-2026`.

Сразу после запуска сайт работает в **демо-режиме**: данные лежат в браузере
и не видны другим устройствам. Это нормально — можно завести свой прайс,
внести закупки и стеллажи, а потом подключить общую базу.
Стереть всё и начать заново: Настройки → «Очистить все данные».

## Общая база (Supabase)

Нужна, чтобы продавцы на телефонах и вы за компьютером видели одни и те же цифры.
Бесплатного тарифа хватает с запасом.

1. Заведите проект на [supabase.com](https://supabase.com).
2. SQL Editor → New query → вставьте содержимое `schema.sql` → Run.
   Файл можно запускать повторно: он только дописывает недостающее и ничего не удаляет.
3. Project Settings → Data API → скопируйте **Project URL**.
   Project Settings → API Keys → скопируйте ключ **anon / public**.
4. Впишите их в `config.js`:

   ```js
   supabaseUrl: 'https://xxxxxxxx.supabase.co',
   supabaseAnonKey: 'eyJhbGciOi...',
   ```

5. Authentication → Users → Add user. Заведите пять пользователей, галочка
   **Auto Confirm User**:

   | E-mail | Пароль | Кто |
   |---|---|---|
   | `admin@lubecontrol.app` | ваш | администратор |
   | `seller1@lubecontrol.app` | свой | продавец СТ-101 |
   | `seller2@lubecontrol.app` | свой | продавец СТ-102 |
   | `seller3@lubecontrol.app` | свой | продавец СТ-103 |
   | `seller4@lubecontrol.app` | свой | продавец СТ-104 |

   На сайте они вводят только логин (`admin`, `seller1`), домен подставляется сам.
   Роль, имя и закреплённый стеллаж подтягиваются автоматически из таблицы `user_seed`.

6. Залейте обновлённый `config.js` в репозиторий. В шапке сайта вместо жёлтой
   полосы «Демо-режим» появится зелёная «Общая база подключена».

**Про ключ anon:** он публичный по задумке, его видно в коде любого сайта на Supabase.
Данные закрывает Row Level Security — политики уже прописаны в `schema.sql`:
продавец меняет остатки только своего стеллажа, прайс и стеллажи правит только админ.

| `seller4` | `Rack104-Oil` | продавец | СТ-104 |

Пароли в `config.js` работают **только в демо-режиме**. С подключённым Supabase
пароль проверяет сервер, а в файле остаются логин, роль, имя и стеллаж —
поле `password` можно вычистить.

Смените пароли перед тем, как давать сайт людям.

## Как это работает

Порядок простой:

1. **Прайс** — заводите товар: название, фирма, объём, артикул, закупка, продажа.
2. **Закупки** — вносите поставку: от кого, почём, сколько, как оплатили. Товар встаёт на склад.
3. **Стеллажи** — добавляете точку и ставите на неё позиции из прайса, пополняете со склада.
4. **Движения** — сквозной журнал: закупили, отгрузили, продали, свернули.

Остаток склада считается сам: закуплено минус отгружено на стеллажи.
Он виден в закупках, в прайсе по каждой позиции и в шапке раздела «Стеллажи».

Сайт поставляется **пустым** — никаких демонстрационных позиций и стеллажей.

## Что умеет

### Администратор

**Стеллажи** — карточка на каждую точку: фото, адрес, продавец, остаток по каждой позиции
квадратиками (один квадрат — одна канистра), статус точки, продажи за период.
Пополнение поштучными счётчиками с итоговой суммой закупки, кнопка «Заполнить всё до максимума».
Маршрут пополнения справа: куда ехать и сколько везти, выгрузка списка в CSV.

**Прайс** — справочник всех жидкостей: категория, название, фирма, объём, артикул,
закупка, продажа, маржа в рублях и процентах, остаток на складе, сколько стоит на стеллажах,
закуплено всего, продано и выручка за 30 дней. Сортировка по любой колонке, поиск,
фильтр по категории. Ненужное уходит в архив — история продаж сохраняется,
вернуть можно в любой момент. Позиции на стеллажи ставятся только отсюда:
правите цену в прайсе — она меняется везде.

**Закупки** — что привезли на склад: дата поставки, товар из прайса, поставщик, категория,
объём, артикул, цена входящая, количество, способ оплаты. Сверху итоги: закуплено,
потрачено, средняя цена, число поставщиков, остаток склада и разбивка по способам оплаты.
Фильтры по периоду, категории, поставщику и оплате, поиск, сортировка, выгрузка в CSV.
Свежая цена закупки по галочке уезжает в прайс и на все стеллажи, где позиция стоит.

**Движения товара** — каждая штука: когда, где, что, какая операция, ± количество,
цена, сумма, маржа, остаток после операции, кто сделал. Закупки идут сюда же —
у них вместо стеллажа стоит «склад». Фильтры по периоду, стеллажу и типу операции,
поиск, выгрузка в CSV.

**Настройки** — пороги, бонус, цвета, надписи и категории меняются ползунками
прямо на экране, результат виден сразу. Кнопка «Скачать config.js» собирает готовый
файл с вашими значениями — залили в репозиторий, и правки увидели все.

### Продавец

Свой стеллаж с фото, продажа в один тап, отмена ошибочной продажи в течение
заданного времени, итоги смены с бонусом, заявка на пополнение,
приём поставки и сверка остатков поштучными счётчиками.
Отдельной строкой видно, на каком этапе поставка: «Администратор увидел заявку» →
«Поставка собрана, везём к вам». Экран рассчитан на телефон.

## Настройка под себя

Всё, что обычно хочется поменять, лежит в `config.js`:

```js
rules: {
  lowThreshold: 35,      // ниже этой доли вместимости остаток «низкий», %
  cancelWindowMin: 10,   // сколько минут продавец может отменить продажу
  bonusPercent: 10,      // бонус продавца от выручки, %
  defaultMax: 10,        // вместимость новой позиции по умолчанию
  routeDays: 7,          // окно «продано» в карточке стеллажа, дней
  photoWidth: 900,       // до какой ширины ужимать фото стеллажа, px
  photoQuality: 72       // качество JPEG для фото, %
}
```

Дальше в файле — цвета, надписи, категории прайса, способы оплаты закупок и аккаунты.
Каждая строка подписана.

Удобнее подбирать значения мышкой: войдите администратором → **Настройки** →
покрутите → **Скачать config.js** → залейте файл в репозиторий.
Правки из панели живут только в вашем браузере, пока файл не залит, — так и задумано,
чтобы подбирать спокойно.

Если `config.js` удалить, сайт продолжит работать на встроенных значениях.

## Фото стеллажей

Админ загружает снимок в карточке стеллажа (карандаш справа вверху).
Сайт сам ужимает фото до размеров из настроек и кладёт его в базу —
продавец видит, как полка должна выглядеть. В демо-режиме фото занимает место
в памяти браузера, поэтому для нескольких точек с фото лучше подключить Supabase.

## Локальный запуск

Просто откройте `index.html` в браузере — всё работает, включая `config.js`.
Если браузер ругается на локальные файлы, поднимите статический сервер:

```bash
python3 -m http.server 8000
```

и откройте `http://localhost:8000`.

## Структура данных

| Таблица | Что хранит |
|---|---|
| `catalog` | прайс: категория, название, фирма, объём, артикул, закупка, продажа, архив |
| `purchases` | закупки: дата поставки, товар, поставщик, цена, количество, сумма, способ оплаты |
| `racks` | стеллажи: код, СТО, адрес, пост, продавец, фото |
| `items` | позиции на стеллажах: ссылка на прайс, остаток, вместимость |
| `ops` | движения: тип, количество, цена, себестоимость, сумма, маржа, остаток после, кто |
| `requests` | заявки и статус поставки: увидел, собрана, принято |
| `profiles`, `user_seed` | пользователи, роли, закреплённые стеллажи |

---

## Обновление

Сайт — один файл. Чтобы обновить, замените `index.html` в репозитории.
`config.js` при этом не трогается, все ваши настройки остаются.
