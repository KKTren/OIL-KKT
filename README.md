# Lube Control

Сайт для мониторинга остатков масла на стеллажах СТО.
Продавец отмечает продажу в один тап — администратор сразу видит остаток и собирает маршрут пополнения.

Статический сайт: только HTML, CSS и JS, никакого сервера. Поэтому его можно бесплатно
разместить на GitHub Pages, а за общую базу отвечает Supabase.

---

## 1. Что внутри

```
index.html            вход
admin.html            панель администратора
seller.html           рабочее место продавца (на телефоне превращается в мобильный экран)
assets/css/app.css    все стили
assets/js/config.js   ← ЕДИНСТВЕННЫЙ файл, который нужно править под себя
assets/js/store.js    работа с данными: Supabase или localStorage
assets/js/auth.js     вход и сессия
assets/js/ui.js       кнопки, окна, уведомления
assets/js/login.js    логика страницы входа
assets/js/admin.js    логика админки
assets/js/seller.js   логика экрана продавца
supabase/schema.sql   SQL для создания базы (выполнить один раз)
.nojekyll             нужен GitHub Pages, не удалять
```

## 3. Быстрый старт без всего

Откройте `index.html` в браузере — сайт заработает в **демо-режиме**:
все данные лежат в этом браузере. Удобно показать заказчику, но продажа продавца
на его телефоне не появится у вас в админке. Для настоящей работы — раздел 5.

---

## 4. Публикация на GitHub Pages

1. Создайте репозиторий на GitHub, например `lube-control` (можно публичный, можно приватный —
   Pages работает и там, если у вас платный план; для бесплатного нужен публичный).
2. Загрузите в него **содержимое** этой папки — так, чтобы `index.html` лежал в корне репозитория,
   а не внутри вложенной папки.
   Через сайт: **Add file → Upload files**, перетащить всё, **Commit changes**.
   Через консоль:
   ```bash
   git init
   git add .
   git commit -m "Lube Control"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/lube-control.git
   git push -u origin main
   ```
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch**,
   ветка `main`, папка `/ (root)` → **Save**.
4. Через 1–2 минуты сайт открыт по адресу `https://ВАШ_ЛОГИН.github.io/lube-control/`.

Дальше любой `git push` (или правка файла прямо на GitHub) обновляет сайт автоматически.

**Если нужен свой домен:** Settings → Pages → Custom domain, вписать домен и добавить у регистратора
CNAME на `ВАШ_ЛОГИН.github.io`. HTTPS GitHub выпустит сам.

**Альтернативы GitHub Pages** (всё бесплатно, любой подойдёт):

| Где | Плюс | Как |
|---|---|---|
| **GitHub Pages** | уже есть аккаунт, ничего нового | как выше |
| **Cloudflare Pages** | быстрее в РФ, свой домен проще | подключить репозиторий, build command оставить пустым |
| **Netlify** | можно просто перетащить папку мышью | netlify.com → Add new site → Deploy manually |
| **Vercel** | автодеплой из GitHub | vercel.com → Import Git Repository |

## 5. Подключение общей базы (Supabase)

Без этого шага сайт живёт в демо-режиме. Занимает минут десять, платить не нужно.

1. Заведите проект на [supabase.com](https://supabase.com) → **New project**.
   Регион выберите поближе (Frankfurt).
2. **SQL Editor → New query** → вставьте целиком файл `supabase/schema.sql` → **Run**.
   Создадутся таблицы, права доступа и стартовые стеллажи СТ-101…СТ-104.
3. **Authentication → Users → Add user → Create new user** — пять раз,
   каждый раз включая галочку **Auto Confirm User**:

   | Email | Password |
   |---|---|
   | `admin@lubecontrol.app`   | `Oil-Admin-2026` |
   | `seller1@lubecontrol.app` | `Rack101-Oil` |
   | `seller2@lubecontrol.app` | `Rack102-Oil` |
   | `seller3@lubecontrol.app` | `Rack103-Oil` |
   | `seller4@lubecontrol.app` | `Rack104-Oil` |

   Роль и стеллаж подставятся сами — за это отвечает таблица `user_seed` из schema.sql.
   На сайте по-прежнему вводится просто `admin`, `seller1` и так далее.
4. **Project Settings → Data API** скопируйте **Project URL**,
   **Project Settings → API Keys** — ключ **anon / public**.
5. Впишите оба значения в начало `assets/js/config.js`:
   ```js
   supabaseUrl: 'https://xxxxxxxx.supabase.co',
   supabaseAnonKey: 'eyJhbGciOi...',
   ```
6. Закоммитьте изменённый `config.js` и обновите сайт.
   Вверху страницы появится зелёная строка «Общая база подключена».

Теперь продажа на телефоне продавца меняет цифру в вашей админке в ту же секунду —
без перезагрузки страницы.

## 6. Про безопасность — честно

- `anon`-ключ Supabase **публичный по своей природе**, его видно в исходниках любого сайта.
  Данные защищает не он, а правила доступа (RLS) из `schema.sql`: продавец может менять
  остатки только своего стеллажа, создавать стеллажи и позиции может только администратор.
- А вот **пароли в `config.js` видны любому**, кто откроет исходный код страницы.
  Они лежат там только ради кнопок быстрого входа и демо-режима.
  Когда подключите Supabase и покажете сайт реальным СТО — поставьте в конфиге
  `showPasswords: false` и удалите поля `password` у аккаунтов.
  Пароль тогда проверяет только сервер Supabase, а в коде его не остаётся.
- Поменяйте пароли из таблицы выше на свои: они есть в этом README, а значит,
  их видел не только вы.

## 7. Что здесь уже работает

**Администратор**

- живые KPI: стеллажи в норме, общий остаток, требующие пополнения, пустые позиции;
- фильтры по статусу и поиск по СТО, адресу, коду, продавцу;
- `−1` — списать позицию вручную;
- «Пополнить» — заполнить стеллаж до максимума, заявка продавца при этом закрывается;
- «История» — операции по конкретному стеллажу;
- «+ Позиция» и «Добавить стеллаж» — расширение сети;
- «Маршрут» — точки на день по критичности, со скачиванием списка в CSV;
- «Экспорт остатков» и «Журнал» — выгрузка в CSV (открывается в Excel);
- график продаж за 7 дней и лидеры продаж считаются из реального журнала.

**Продавец**

- «Продал 1 шт» — крупная кнопка на каждой позиции;
- отмена ошибочной продажи в течение 10 минут (настраивается в конфиге);
- итоги смены: количество, выручка, бонус 10 %;
- «Запросить пополнение» — заявка уходит администратору;
- «Принять поставку» — заполнить стеллаж после приезда курьера;
- «Сверка остатков» — вписать фактическое количество после пересчёта,
  расхождение попадает в журнал.

## 8. Настройки под себя

Всё в `assets/js/config.js`:

| Параметр | Что делает |
|---|---|
| `lowThreshold` | доля остатка, ниже которой статус «низкий» (0.35 = 35 %) |
| `cancelWindowMin` | сколько минут продавец может отменить свою продажу |
| `bonusPercent` | процент бонуса продавца от выручки |
| `showPasswords` | показывать ли на входе кнопки быстрого входа с паролями |
| `accounts` | список пользователей, ролей и стеллажей |
| `demoRacks` | стартовые данные демо-режима |

Названия масла, цены и вместимость полок меняются прямо в интерфейсе
(«+ Позиция» в карточке стеллажа) либо в `supabase/schema.sql` до первого запуска.
